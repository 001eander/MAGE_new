# MAGE 源码逐读 · 邮件正文排版设计 spec

这份 spec 是三个设计方向唯一的共同输入。三版各自独立工作，只看这份 spec 与 `content.json`，互不参考。

## 1. 这是什么

一份教材式的源码讲解文档。第 1 篇讲 MAGE 主模型 `models_mage.py`（397 行）：先交代模型在做什么（整张图被冻结的 VQGAN 编码成 16×16=256 个编号，模型在这 256 个编号上做类似 BERT 的掩码预测），然后按文件顺序逐节拆解 `Attention`、`Block`、`LabelSmoothingCrossEntropy`、`BertEmbeddings`、`MlmLayer`、`MaskedGenerativeEncoderViT` 的构造与 `forward_encoder` / `forward_decoder` / `forward_loss` / `forward`，最后是两个工厂函数。

内容形态是混合的：概念叙述、带行号引用的代码片段（23 段）、要点清单、以及 9 张流程图。三种信息的密度和视觉重量完全不同，这是排版要解决的核心矛盾。

## 2. 受众与场景

唯一读者是文档作者本人，用途是复习和日后回看这份代码。阅读场景是电脑或手机上的邮件客户端，通常是「扫一眼找重点」，很少从头读到尾。所以文档需要两条读取路径同时成立：**30 秒内定位到某一节**，和 **10 分钟顺着读通一遍**。

系列形式：共 5 篇，本篇是第 1 篇。系列名可用「MAGE 源码逐读」，后续篇目为下游分类 `models_vit_mage.py`、预训练引擎 `engine_pretrain.py`、微调与线性探测 `engine_finetune.py`、入口脚本 `main_*.py`。每篇都需要能被认出来自同一系列。

## 3. 核心信息与内容要点

- 模型概览：编号空间掩码预测的数据流
- 依赖与导入（1–13 行）

- `Block`（47–69 行）：pre-norm 残差块
- `LabelSmoothingCrossEntropy`（72–87 行）：标签平滑

- `MlmLayer`（127–143 行）：点积分类头

- `initialize_weights` / `_init_weights`（235–264 行）
- `forward_encoder`（266–333 行）：抽遮挡比例、造两种掩码、拼类槽、丢 token

- 这一篇的要点（5 条结论）
- 9 张架构图：预训练数据流、编码器内部、解码器内部、损失流、两种分类头对比、类结构、下游分类路径、训练时序、三个入口脚本分工

## 4. 情感基调

工具感、可信、克制但不寡淡。读者是自己，所以允许速记式标注、直白的判断句（比如「这四样东西前向路径里根本不用」），不需要科普腔，也不需要「欢迎阅读」这类客套。气质关键词：**精确、安静、有索引感**。

## 5. 输出格式与尺寸（必填）

- 单个 HTML 文件，**单栏**
- 正文列宽 **820–900px**，在 1440×900 视口下居中
- 必须在 **375px** 宽度下正常重排（单栏、字号不缩水到不可读）
- **无 JavaScript**、无外部网络请求（字体用系统栈；草稿阶段图片可用相对路径）
- 这是**邮件正文的排版稿**，邮件客户端会剥掉一部分 CSS，所以不要依赖只有浏览器才有的能力

三版必须使用同一尺寸，否则无法横向对比。

## 6. 已知约束

**内容完整性（硬）**：`content.json` 里的 16 个 section、23 段代码、9 张图必须全部出现在产出里，文案一字不改。占位符、省略号、「以下略」都不接受。

**代码是重头**：23 段代码是这份文档的主体之一，每一版都要给出明确的代码呈现策略——字号、行高、长行（最长 116 字符）怎么处理、有没有行号、有没有语法高亮的配色逻辑。顺手提醒：深色代码块视觉重量很大，连续出现会压过正文结论，这是现版本的毛病之一。

**图的尺寸差异**：9 张图从 110px 到 1757px 高不等，宽度都是 874px。要给出处理策略：高图是否需要缩窄、是否需要和说明文字左右对位、多张图之间怎么分隔。

**系列识别**：需要让读者第一眼看出这是「第 1 篇 / 共 5 篇」，并知道后面还有哪些篇目。

**邮件客户端红线**：不使用 CSS 变量 `var()`（草稿可以用，但要能整体展开）、不使用 `position: fixed`、不依赖 `:hover` 传递信息。

**反 AI slop 清单（禁用）**：激进紫渐变；emoji 当图标；圆角卡片 + 左侧彩色 border accent 这个组合；Inter / Roboto / Arial 作为 display 字体；均匀深蓝底 + 通用霓虹 glow。

**阅读性硬底线（任何风格温度都不豁免）**：正文 ≥15px，标签与注释 ≥12px，正文对比度 ≥4.5:1。留白必须是构图——首屏要有明确的视觉锚点、视线有落点，不是内容缺席造成的死白。

**三版骨架必须结构性不同**：导航方式、首屏结构、章节头部、代码块处理、图的处理，至少要有一半不同。不许两版共用同一骨架只换色换字体。

## 8. 视觉母题假设

这份内容独有的东西是**编号空间**。整篇讲的就是「图像 → 256 个编号 → 盖住一部分 → 猜回来」，别的主题不会长成这个样子。可作为 form 的种子：**位置网格、被遮挡的空位、编号序列、以及「哪些位置露出来 / 哪些被盖住」的二分**。

第二个可选母题是**掩码的两种叠加**：编码器丢掉的 128 个位置是遮盖集合的子集，代码里用 `token_drop_mask` 和 `token_all_mask` 两个掩码表示。这个「一个集合套在另一个集合里」的结构本身就能成为版式里的一个视觉装置。

要求：每个方向交付时用一句话说明「form 来自内容的哪里」。写不出来说明在套模板。
