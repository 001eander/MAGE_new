01

这一篇讲什么

系列前两篇按文件走：第 1 篇讲 models_mage.py 怎么把编号猜回来，第 2 篇讲 eval_exp.py 怎么把生成结果变成可核对的数字。这一篇换个走法，按四条线把整个项目串一遍——模型结构、训练与推理的数据流、几处能推导清楚的理论、以及结果该怎么读。

这么走的原因是，前两篇分开看时有些东西看不出因果。比如标签平滑为什么会让点积头「换一个相近的小块」、为什么一次揭开多个位置会拼出左右对不上的图、为什么两个 FID 必须并排写——这三件事各自散在不同的文件里，但它们的答案都在同一套数学里。放在一起讲，推导才立得住。

图像→冻结 VQGAN→256 个编号→遮住一部分→编码器→解码器→编号分数→（训练）平滑交叉熵 ／（推理）逐步揭开→解码成图→指标

四条线各自的落点

  • 结构：编号空间是 1024 个词的离散空间，模型全程不碰像素；词表 2025 = 1024 编号 + 1000 类别 + 1 mask；类槽用一个写死的编号 1100 表示。
  • 数据流：训练时编码器固定丢掉一部分位置，解码器拿回全部 257 个槽；推理时一个位置都不丢，但要在 20 步里从全遮走到全揭。
  • 理论：训练目标是逐位置的条件似然，采样器用的是它的平均场松弛；分类头的差别可以用一个带约束的最优化问题写清楚；FID 的量化下界来自解码的确定性。
  • 结果：论文的数字是在 ImageNet-256 上、ViT-B 11.1；本实验跑的是 Tiny-ImageNet 放大到 256，那个数字不能拿来比。
注
这一篇里出现的公式都是从头推的，代码行号指向实际文件。本实验自己的结果数字不在仓库里（outputs/ 在集群上），所以「结果」那一部分只写口径和清单，不编数字。
02

编号空间：VQGAN 之后剩下什么

models_mage.py 158–171

整个项目建立在一个替换上：把图像换成 256 个编号，后面所有事情都在编号上做。做替换的是 VQGAN 的编码器，它把 256×256 的图压成 16×16 个特征，每个特征在 1024 个词里挑最近的一个。

Python · 编号空间：VQGAN 之后剩下什么01 / 15
config = OmegaConf.load('config/vqgan.yaml').model
self.vqgan = VQModel(ddconfig=config.params.ddconfig,
                     n_embed=config.params.n_embed,
                     embed_dim=config.params.embed_dim,
                     ckpt_path=vqgan_ckpt_path)
for param in self.vqgan.parameters():
    param.requires_grad = False

self.codebook_size = config.params.n_embed
vocab_size = self.codebook_size + 1000 + 1
self.fake_class_label = self.codebook_size + 1100 - 1024
self.mask_token_label = vocab_size - 1

这五行把编号空间的边界定死了。逐条看：

  • codebook_size = 1024：一张图的编号取值是 0..1023。这个数字决定了分类头要输出多少类。
  • vocab_size = 2025：1024 个编号之外，多出 1000 个位置留给分类任务的类别编号，最后再加 1 个专给遮盖用。多出来的 1001 个不是为了生成服务的，它们的 logits 在算生成损失时会被切掉。
  • fake_class_label = 1100：写在序列最前面那个位置的编号。它落在类别编号区间里，和真实的 0..1023 不会碰撞，它对应的那一行嵌入是可学习的，作用等价于 BERT 的 [CLS]。
  • mask_token_label = 2024：遮盖位置用它替换。注意它是一个合法编号，模型得学会「看到 2024 说明这里需要预测」，而不是把它当成一个普通的词。
敲黑板

VQGAN 在构造函数里就被 requires_grad = False 冻结了，而且整个项目里它从不参与更新。这意味着像素层面的上限在训练开始前就定好了：模型再准，输出也只能是「同一张 256×256 图先编码再解码」的结果。这一句是后面 FID 那一节的地基。

位置信息由两张表提供：BertEmbeddings.position_embeddings 是可学习的 257 行表，和编号一起查表相加。文件里还有一套正弦余弦 pos_embed 和 decoder_pos_embed，它们是 MAE 骨架留下的，前向路径里不会走到。

点积头 MlmLayer

Python · 两个分类头04 / 15
def forward(self, x, word_embeddings):
    mlm_hidden = self.ln(self.gelu(self.fc(x)))
    word_embeddings = word_embeddings.transpose(0, 1)
    logits = torch.matmul(mlm_hidden, word_embeddings)
    return logits + self.bias

关键是最后一行的权重来自哪里。调用方传进来的是 self.token_emb.word_embeddings.weight.data.detach()——分类权重就是词嵌入表本身，而且梯度不从这里回流。于是隐向量只能通过内积和词向量比较，它没有自己独立的一套类别方向。

这一句是整个项目里最有后果的一行。下一篇要推的「最优解被限制在词向量张成的空间里」，说的就是它。

独立分类头

Python · 两个分类头05 / 15

一行。token_classifier 的 1024 行权重完全自由，不受词嵌入表的任何约束。它多出来的参数量是 1024 × decoder_embed_dim，ViT-B 上是 78 万，占总参数量的很小一部分，但它换来的是完全不同的解空间。

两个掩码，一个套在另一个里

Python · 预训练一步：从图像到损失07 / 15
mask_rate = self.mask_ratio_generator.rvs(1)[0]
num_dropped_tokens = int(np.ceil(seq_len * mask_ratio_min))
num_masked_tokens = int(np.ceil(seq_len * mask_rate))

while True:
    noise = torch.rand(bsz, seq_len, device=device)
    sorted_noise, _ = torch.sort(noise, dim=1)
    cutoff_drop = sorted_noise[:, num_dropped_tokens-1:num_dropped_tokens]
    cutoff_mask = sorted_noise[:, num_masked_tokens-1:num_masked_tokens]
    token_drop_mask = (noise <= cutoff_drop).float()
    token_all_mask = (noise <= cutoff_mask).float()
    if token_drop_mask.sum() == bsz*num_dropped_tokens and token_all_mask.sum() == bsz*num_masked_tokens:
        break
  • mask_rate 每步只抽一个标量，这一批数据共用。分布是截断正态，默认均值 0.55、标准差 0.25，截断到 [mask_ratio_min, mask_ratio_max]。
  • num_dropped_tokens 由 mask_ratio_min 决定，和抽到的比例无关。这是编码器固定要丢掉的数量，默认 0.5 时是 128 个。
  • num_masked_tokens 由抽到的比例决定，总是大于等于前者。两个集合是包含关系：token_drop_mask ⊂ token_all_mask。
  • 用「排序后取第 k 小值当阈值」而不是直接取前 k 个，是为了让输出保持布尔矩阵的形状；噪声里出现并列值时选中个数会对不上，while True 就是处理这种情况的。

06

训练目标到底是什么

理论推导 · 一

把上面这几步抽象出来，训练在最小化的是这样一个量。记编号图为 x ∈ {0..1023}^256，M 是被遮盖的位置集合，C 是编码器看得到的位置集合，q_i(v | x_C) 是模型在位置 i 上给出的分布。训练损失就是

L = E_M [ (1/|M|) Σ_{i∈M} −log q_i(x_i | x_C) ] ＋ 标签平滑项

这里的期望是对遮挡过程取的：先抽 r，再抽哪些位置进 M。标签平滑加进来之后，每一项从 −log q_i(x_i) 变成 −(1−ε)·log q_i(x_i) − ε·(1/V)Σ_v log q_i(v)，也就是把「正确答案占 100% 置信」改成「占 90%」。

它不是联合似然的极大化

这一点值得说清楚，因为它直接解释了后面的采样行为。对固定的 M 和 C，把模型在每个位置上的对数概率加起来，和整块的对数概率比一下：

Σ_{i∈M} log p(x_i | x_C) ≥ log p(x_M | x_C)

左边是各位置边缘分布的对数和，右边是这一块的联合分布。不等号的方向来自熵的次可加性：H(X_M | X_C) ≤ Σ_i H(X_i | X_C)。换句话说，逐位置预测的这个目标，是在优化联合似然的一个上界——它比真正要做的事情宽松。

宽松在哪里？宽松在它不要求模型刻画 M 内部位置之间的依赖。位置 i 和位置 j 如果都在被遮的集合里，模型对它们的预测各自只看 C，互相之间不需要一致。这正是论文为什么要让解码器在每个位置上「分别」算概率。

注
训练时的编码器看到的是缩过的 129 个位置，解码器看到的是对齐的 257 个槽。两者的差别不影响上面的结论：对解码器来说，被遮位置之间依然没有互相依赖的输出结构。
07

为什么一次揭多个会拼出接不上的图

理论推导 · 二

接着上面那个上界往下走。既然训练时就把「位置之间互相依赖」这一层省掉了，采样时自然拿不到它。采样器在每一步做的是

从 Π_{i∈M} q_i(x_i | x_C) 里抽一样本

这是一个平均场近似：用各位置的边缘分布的乘积去代替真正的联合分布。当被遮的位置互相独立时它是对的；当它们强相关时它会失真。

图 3 · 推理：两套采样循环，只是揭开次序不同

这和半 A 半 B 实验的对应

把 A 的左半和 B 的右半拼成一张编号图，接缝以左全部由 A 决定，接缝以右全部由 B 决定。这是一个强相关的联合分布：知道左边是 A，右边的合理取值就被限制住了。而采样器一次从乘积分布里抽一批位置，抽的时候彼此不知道对方抽了什么，于是接缝两侧可以各自成立、合起来不成立。

一次只揭一个位置为什么好一些：抽完立刻把它变成可见，下一步的条件里就包含了它。这一步的松弛只涉及一个位置，256 步累积下来每一步都只承担一份局部误差。

  • step 数越多、每步揭的越少 → 乘积近似的误差越小，但总计算量越大。cosine 调度用 20 步，uncover1 用最多 256 步。
  • 当 |M| = 1 时乘积分布和真实分布完全一样，因为只有一个位置，不存在「互相依赖」。所以一次揭一个的位置数是理论上最干净的极限。
  • 这也解释了为什么论文默认的多步采样会把已经猜对的位置再遮回去——重遮是一种重新引入全局一致性的手段，代价是抹掉已经落子的事实。
08

标签平滑把目标改成什么

理论推导 · 三

设某个位置的 logits 是 z ∈ R^V，正确答案是 y。平滑交叉熵可以写成

L(z) = −(1−ε)·z_y − ε·(1/V)·Σ_v z_v ＋ log Σ_v exp(z_v)

对 z 求梯度：

Python · 标签平滑把目标改成什么11 / 15
∂L/∂z = softmax(z) − [ (1−ε)·e_y + ε/V · 1 ]

所以如果 logits 可以任意取，最优解就是让模型分布等于平滑后的目标分布——正确答案占 1−ε，其余 1024 个词平分 ε。ε=0.1 时答案占 0.9，剩下每个约 0.0001。

关键在于 logits 不能任意取。分类头的写法决定了 z 和隐向量 h 之间是什么关系，而不同的头给出完全不同的解空间。这就是下面两节要分开推的原因。

09

点积头：一个带约束的最优解

理论推导 · 四

点积头的 logits 是 z_v = h · w_v，其中 w_v 是第 v 个词的嵌入向量，h 是解码器输出的隐向量。把 z = W h 代进上一节的损失，对 h 求梯度：

Python · 点积头：一个带约束的最优解12 / 15
∂L/∂h = W^T ( softmax(W h) − t )   其中 t = (1−ε)·e_y + ε/V · 1

令它等于零。记 p = softmax(z) 是模型给出的分布，w̄ = (1/V) Σ_v w_v 是全部词向量的平均，一阶条件整理成：

Σ_v p_v · w_v = (1−ε)·w_y ＋ ε·w̄

这个式子的读法是：模型用自己的概率去加权平均词向量，得到的那个向量必须等于「正确答案向量与全体平均值的一个固定混合」。隐向量 h 本身被消掉了——它只充当一个中间量，真正被约束住的是输出分布的矩。

图 4 · 评测流水线：一张 metrics.json 的来路

正交的码本下，答案不会跑掉

如果 1024 个词向量两两正交（同时 w̄ 落在它们的张成空间里），满足上面这个向量等式的分布是唯一的：把 t 按正交基分解，得到的系数就是 p。此时 p 正好等于平滑后的目标分布，最大概率落在 y 上，argmax 不会错。

但 VQGAN 的码本是学出来的，相邻的块本来就相似，词向量之间存在明显的相关性。这时上面那个向量等式有多组解：把一部分概率从 w_y 挪给另一个和它方向接近的 w_{y'}，加权和几乎不变，等式仍然近似成立，而 argmax 已经换人了。

敲黑板

这就是「换相近的小块」的完整机制。它需要两个条件同时成立：标签平滑把一部分概率强制分出去（ε > 0），以及词向量之间存在相关性（VQGAN 码本天然如此）。少任何一个，argmax 都会老老实实停在正确答案上。所以这个现象只在「点积头 + 标签平滑」这一格里容易出现。

把它和第 1 篇里那四种组合对照一下，预测就很清楚：

  • 点积 + 不平滑（ε=0）：目标是 Σ p_v w_v = w_y。正交时唯一解是 e_y；有相关时虽然也有多解，但没有「必须分出去」的那部分概率，argmax 更容易停在 y 上。
  • 点积 + 平滑：两个条件都满足，最容易出现「换成相近的编号」。
  • 独立头 + 不平滑：U 自由，可以把 y 的分数抬到任意高，精确记住编号。
  • 独立头 + 平滑：U 仍然自由，虽然目标分布被摊开了，但把 y 的分数抬到最高这件事不受影响，argmax 依然可以是正确答案。
10

线性头为什么能逃出去

理论推导 · 五

独立分类头的 logits 是 z = U h，U 是一个 1024 × D 的自由矩阵，每一行不受其他行约束，也不和词嵌入表共享。从优化的角度看，差别在于可行域：

  • 点积头：z 只能落在 {W h : h ∈ R^D} 这个 D 维子空间里。要实现的分布 t 未必在这个子空间里。
  • 线性头：z 可以取 R^1024 里的任何值——取 U = I、h = z 即可，只要 D ≥ 1024；D < 1024 时也能通过一个线性映射覆盖足够的方向。

可行域不受限的直接后果：上一节那个「矩必须等于某个固定混合」的等式消失了。线性头可以把正确答案的分数抬到任意高、把其余类的分数压到任意低，平滑项只会让整个分布被摊开一点，但摊开之后最大概率仍然在正确答案。

这解释了四种组合里的两种极端

ε = 0 时线性头的目标就是一个 one-hot，它可以把 y 的 logit 做到远高于其他类，等价于把训练集的编号整张记住。ε = 0.1 时目标变成 (0.9, 0.0001, 0.0001, …)，要 argmax 正确只需要 z_y > z_v 对所有 v ≠ y 成立，这件事和「概率被摊开」并不矛盾。

注
所以第 4.1 节那张表的两列不是「谁更好」，而是「谁的可行域更大」。可行域大意味着更可能精确记住训练样本，在 n 小的时候表现为编号全对，在 n 大的时候表现为覆盖不到新样本。两个方向都可以从同一个约束条件读出来。

cosine 调度：每步揭多少

理论推导 · 六

采样循环里，第 t 步之后还剩多少位置没揭开，由这个式子决定：

mask_len(t) = floor( N · cos( π/2 · (t+1)/T ) )，N = 256，T = num_iter

它同时受两道夹取：上限是 sum(unknown) − 1（这一步至少得揭掉一个），下限是 1（至少给下一步留一个）。把 N=256、T=20 代进去，得到的数是

[255, 252, 248, 243, 236, 228, 218, 207, 194, 181,
 166, 150, 133, 116,  97,  79,  59,  40,  20,   0]
图 5 · 为什么一次揭多个会拼出接不上的图

为什么是余弦

把 cos(π/2·u) 看成 u ∈ [0,1] 上的函数，它在这个区间上是凸的（二阶导为负），导数 −π/2·sin(π/2·u) 从 0 单调走到 −π/2。导数就是「每步揭掉的比例」：

第 t 步新揭开的位置数 ≈ N · (π/2T) · sin( π/2·(t+1)/T )

正弦在 [0, π/2] 上单调递增，所以每一步揭开的数量是单调增加的。开头几乎不动，结尾一次揭掉一大片。实际算出来的每步新揭开数是

Python · cosine 调度：每步揭多少14 / 15
1, 3, 4, 5, 7, 8, 10, 11, 13, 13, 15, 16, 17, 17, 19, 18, 20, 19, 20, 20

整体趋势是递增的；floor 取整会带来个别位置上的抖动（第 16 步比第 15 步少一个），连续形式是严格单调的。

这个形状和「模型知识的积累方式」是相配的：开头几乎没有已知位置，模型的信息最少，一次揭太多位置的风险最大；越到后面已知位置越多，条件越来越充分，一次揭一批才安全。和平均场那一节的说法合起来看，每步揭的数量决定了这一步要承担多少「互相依赖被忽略」的误差，余弦调度把这份误差摊成了前小后大。

FID 的分解与量化地板

理论推导 · 七

FID 的定义是两个特征分布之间的距离。记拟合出来的高斯为 N(μ, Σ)，Fréchet 距离是

FID(p, q) = ‖μ_p − μ_q‖² ＋ tr( Σ_p ＋ Σ_q − 2·(Σ_p Σ_q)^{1/2} )

这个表达式不是随手拼的：它正好等于两个高斯分布之间的 2-Wasserstein 距离的平方。这一点有两个直接后果。

后果一：sqrt(FID) 是真正的距离

W₂² 的平方根 W₂ 是度量空间上的距离，满足三角不等式。于是

sqrt(FID(gen, ref)) ≤ sqrt(FID(gen, recon)) ＋ sqrt(FID(recon, ref))

换句话说，FID 本身不能相减：FID(gen, ref) − FID(recon, ref) 没有一个通用的分解含义。能写出来的只有上面那条开平方之后的三角不等式。

注
README 第 4.5 节写的是「(3) 减 (1) 才是分类头、标签平滑、遮挡方式和采样带来的误差」。严格按数学读，那句里的「减」应当理解成并排比较：把两档数字放在一起看，判断生成那一档比量化地板高多少。把 FID 相减当成误差分解会高估地板的贡献，因为三角不等式里的加法量级本来就不同。
图 6 · 两种分类头在最优解处的差别

后果二：地板是真的地板

解码是确定性的：给定编号，get_codebook_entry 加 vqgan.decode 得到唯一的图。所以如果生成出来的编号分布和参照集的编号分布完全一样，那么两边的图像分布也完全一样，此时

FID(生成 vs 参照) = FID(参照重建 vs 参照)

这个等号是严格的，不是近似。metrics.json 里那个 'tokens_exact_equals_vqgan_recon': True 说的就是它。也正是为什么两个 FID 必须并排写：重建那一档是量化本身能达到的最好结果，生成那一档只能站在它上面，两者之间的距离才是模型的事。

还有一件事要提醒：这个「地板」只在生成编号复现了参照编号时才严格成立。模型的编号分布和参照的编号分布不同时，两组图像的分布也会不同，两者之间的差既包含「编号没猜对」，也包含「解码之后放大或缩小了这种差别」。

覆盖率与匹配误差

理论推导 · 八

这两个指标把「生成得像不像训练集」换成了一个可以有向度量的东西。先定义两张编号图之间的距离：

d(x, y) = (1/256) · Σ_{i=1..256} 1[x_i ≠ y_i] 取值在 [0, 1]

就是逐位不等的比例，256 维上的归一化 Hamming 距离。两个指标都是它的极值：

  1. 01覆盖率（训练集 → 生成集）：对每张训练图 x，求 min_g d(x, g)。等于 0 的比例叫完全覆盖，小于等于 16/256 = 6.25% 的比例叫大致覆盖。它回答「训练集里有多少张能在生成结果里被找到」。
  2. 02匹配误差（生成集 → 训练集）：对每张生成图 g，求 min_x d(g, x)。对所有生成图取平均。它回答「生成出来的东西离训练集有多远」。

为什么是两个方向

两个方向测的不是同一件事。覆盖率只看训练集那一侧，即使生成集里只有 1000 张图、张张都在复现训练样本，只要训练样本足够少，覆盖率也能很高。匹配误差只看生成集那一侧，即使生成集把 256 维空间里的一大片都铺开了，只要每张都离某个训练图不太远，这个数也不大。

放在一起读才有意义：

  • 覆盖率接近 1 + 匹配误差很小 → 模型在复现训练集，小 n 上这是可以做到的，因为 1024^256 的搜索空间里要精准命中几个点并不难。
  • 覆盖率低 + 匹配误差大 → 生成结果既不落在训练集附近，也没覆盖住，这通常出现在 n 大、训练轮数不够的时候。
  • 覆盖率低 + 匹配误差小 → 生成的图都在训练图的邻域里，但没有一张精确命中。这是大 n 上比较理想的状态。

大 n 上完全覆盖为什么必然接近 0

完全覆盖要求生成集里存在一张图，256 个编号全部和某张训练图相同。生成张数是 |G|，而编号空间的规模是 1024^256；即使模型把分布学得很准，单张图被精确复现的概率仍然极低。所以 README 第 2.2 节才会说「大 n 完全覆盖可以接近 0，大致覆盖和匹配误差仍要报」——前者失去分辨力，后者还有。

复杂度

直接算需要 |T| × |G| × 256 次比较。n=1000 时要拿 50000 张生成图对 1000 张训练图，是 1.28 × 10¹⁰ 次整数比较；n=10000 时放大十倍。代码里用两层分块（q_batch=32、g_batch=4096）把中间张量的体积压住，这只是内存上的处理，算术总量没有减少。

这两行是推理路径的起点。生成时没有任何位置被丢掉，token_drop_mask 是全零张量，所以编码器看到的是类槽加全部 256 个位置。被遮的位置仍然以 mask_token_label 的身份留在序列里。

循环体里每步要做的事，第 2 篇已经逐行拆过，这里只把两套循环的形状放在一起看：

  • cosine：每步把所有未知位置一起预测，再按置信度遮回一批。遮回的数量由余弦调度决定。已经猜对的位置可能被重新遮住。
  • uncover1：每步只把最有把握的那一个位置定下来，落子即固定。最多 256 步，未知清空就提前退出。

两者的每个位置仍然各自算概率，差别只在揭开的次序。结合平均场那一节：cosine 每步要一次定下一批位置，这批位置之间没有互相依赖；uncover1 每步只承担一个位置的松弛。

README 第 4.3 节专门写了一句：论文默认的 12 步生成会把已经猜对的位置再遮回去，那不是半 A 半 B 实验。原因是重遮会让「接缝周围的替换发生在哪一步」变得不可观察——一批位置被遮掉再重新预测，你看不出新的取值是因为条件变了还是因为噪声换了。

本实验的口径

README 第 2.1 / 4.5 节

本仓库跑的实验和上面那组数字不是同一个实验，这件事在 README 里被反复强调，理由有三个。

  1. 01数据不同。本实验用 Tiny-ImageNet，原图 64×64，训练和评测前 Resize(256, BICUBIC) + CenterCrop(256) 放大到 256。放大这一步本身会引入模糊和块状伪影，FID 分布和原生 256×256 的图完全不同。
  2. 02训练集规模不同。论文用完整 ImageNet-1K（128 万张），本实验按 n = 1, 2, 10, 100, 1000, 10000 逐档跑。
  3. 03FID 实现不同。本实验用 pytorch-fid 的 calculate_fid_given_paths（TF Inception 2015-12-05，2048 维），和 LGANs-TT 的 realdata.py 一致；论文的官方评测命令用的是 torch-fidelity。两边主干网络同为 Inception，但预处理和版本差异会带来小数级别的偏移。
敲黑板

合并起来读：metrics.json 里 source.fid_comparable_to_paper 这个字段永远是 false，Tiny 上的 FID 不能和 11.1 比。它只能在本实验内部横向比：同一个 n 下的不同设置之间、同一个设置下的不同 n 之间。

能比的是这三组

  • 同一个 n 下，四种组合（点积／独立头 × 平滑／不平滑）之间。
  • 同一种组合下，n = 1 → 2 → 10 → 100 → 1000 → 10000 的走势，以及它离该数据上的 VQGAN 重建 FID 还有多远。
  • 0.5-1 与 0-1 两种遮挡分布在同一个 n 上的差别。

顺带说一下 n=10000 那一档：它要生成 50000 张图，和论文的生成张数一致，是唯一一档在「图数」上对齐的配置。要对齐的只有图数，数据本身仍然不同。

要点汇总

  1. 01整个项目只做一件事：把图像换成 256 个编号，然后在这个离散空间里做掩码预测。像素只在 VQGAN 里出现一次，而且 VQGAN 全程冻结。
  2. 02词表 2025 = 1024 编号 + 1000 类别 + 1 mask。类槽用写死的编号 1100，遮盖用写死的编号 2024，两者都落在真实编号区间之外，不会碰撞。
  3. 03训练时编码器固定丢掉 mask_ratio_min 比例的位置，解码器拿回全部 257 个槽；两个掩码是包含关系。推理时一个位置都不丢。
  4. 04训练目标是逐位置的条件似然，在数学上是联合似然的一个上界——它不要求刻画被遮位置之间的依赖。采样器实际用的是这份目标的平均场松弛，一次揭多个位置之所以会拼出接不上的图，根源就在这里。
  5. 05点积头的最优解满足 Σ p_v w_v = (1−ε)w_y + ε w̄。标签平滑强制分出一部分概率，码本向量之间又存在相关性，两个条件合起来才让 argmax 可能离开正确答案。独立头因为可行域不受限，两个条件都不受约束。
  6. 06余弦调度让每步揭开的位置数单调递增，把平均场误差摊成前小后大。
  7. 07FID 是 2-Wasserstein 距离的平方，所以能写三角不等式的是 sqrt(FID)；FID 本身不能相减。量化地板在「生成编号复现参照编号」时是严格等式。
  8. 08覆盖率和匹配误差是同一套 Hamming 距离的两个方向，一个看训练集被找到多少，一个看生成集离训练集多远。大 n 上完全覆盖必然接近 0，这个数在大 n 上失去分辨力。
  9. 09论文的 11.1（ViT-B）是 ImageNet-256 上的数字。本实验是 Tiny-ImageNet 放大到 256，fid_comparable_to_paper 永远是 false，只能在本实验内部横比。
  10. 10本实验的结果文件在集群上，不在仓库里。仓库维护的是清单和口径，这两样东西本身就是结果该怎么读的前提。
